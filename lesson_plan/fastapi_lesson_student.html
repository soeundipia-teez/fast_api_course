개념 1FastAPI 와 uvicorn

FastAPI는 '어떤 URL 로 요청이 오면 어떤 함수를 실행할지'를 정하는 웹 프레임워크이고, uvicorn은 실제로 TCP 8000번 포트를 열고 HTTP 요청을 받아 FastAPI 에 넘겨주는 서버 프로그램입니다. 앞 과정에서 만든 소켓 서버의 bind → listen → accept 를 uvicorn 이 대신해 줍니다.

실행 명령
uvicorn main:app --reload
# main  : main.py 파일
# app   : 그 안의 FastAPI 객체 이름
# --reload : 코드를 저장하면 자동 재시작 (개발용)

async def about():

개념 1ORM: 클래스로 테이블 다루기

SQLAlchemy 는 파이썬 클래스 하나를 DB 테이블 하나로 연결합니다. Base 를 상속하고 Column 으로 컬럼을 적으면 Base.metadata.create_all() 이 테이블을 만들어 줍니다. DB 는 원본 실습과 같은 MySQL 의 my_memo_app 이고, PyMySQL 드라이버로 접속합니다. 접속 정보는 URL 하나에 모두 들어갑니다: mysql+pymysql://계정:비밀번호@호스트:포트/DB이름.

DB 설정과 모델
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    "mysql+pymysql://hyundai:hyundai@localhost:3306/my_memo_app?charset=utf8mb4",
)
engine = create_engine(DATABASE_URL, pool_pre_ping=True)   # 끊긴 연결 자동 복구
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()

class Memo(Base):
    __tablename__ = "memo"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String(100))
    content = Column(String(1000))
2 / 9

개념 2스키마(Pydantic)와 모델은 다르다

모델(SQLAlchemy)은 DB 에 저장되는 모양, 스키마(Pydantic)는 HTTP 로 오가는 JSON 의 모양입니다. 요청 본문은 스키마가 먼저 검사해서 필수 값이 빠지면 422 로 막고, 응답은 response_model 이 필요한 필드만 골라 JSON 으로 바꿉니다.

스키마 3종
class MemoCreate(BaseModel):      # 생성 요청
    title: str
    content: str

class MemoUpdate(BaseModel):      # 수정 요청: 일부만 보내도 됨
    title: str | None = None
    content: str | None = None

class MemoOut(BaseModel):         # 응답
    model_config = ConfigDict(from_attributes=True)   # ORM 객체 → JSON
    id: int
    title: str
    content: str

개념 3Depends 로 DB 세션 빌려주기

get_db() 는 yield 로 세션을 빌려주고, 응답이 끝나면 finally 에서 닫습니다. 라우트 함수는 db: Session = Depends(get_db) 라고 적기만 하면 됩니다. 이렇게 '필요한 것을 선언하면 FastAPI 가 준비해 주는' 방식을 의존성 주입이라고 합니다.

세션 의존성
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

개념 4CRUD 와 HTTP 메서드

같은 /memos/ 경로라도 메서드가 다르면 다른 동작입니다. 수정·삭제 대상이 없으면 HTTPException(404) 를 던져 상태 코드로 알립니다.

생성 예시
@app.post("/memos/", response_model=MemoOut)
def create_memo(memo: MemoCreate, db: Session = Depends(get_db)):
    new_memo = Memo(title=memo.title, content=memo.content)
    db.add(new_memo)
    db.commit()
    db.refresh(new_memo)      # DB 가 만든 id 를 다시 읽어 옴
    return new_memo

기초1. 메모 현황판 API

상황

운영팀이 '지금 메모가 몇 개 있고, 가장 최근에 뭐가 들어왔는지' 대시보드에 띄우고 싶어 합니다.

요구사항

  • GET /memos/summary
  • 응답: {"count": 전체 개수, "latest": 가장 최근 메모 | null}
  • 메모가 하나도 없으면 latest 는 null
힌트 보기
  • 개수는 db.query(Memo).count()
  • 최근 메모는 order_by(Memo.id.desc()).first()
  • ORM 객체를 JSON 에 넣을 때는 MemoOut.model_validate(객체)

확인 방법

직접 확인
curl http://127.0.0.1:8000/memos/summary
# {"count":2,"latest":{"id":2,"title":"회의","content":"3시 B동"}}

기본2. 검색과 페이지 나누기

상황

메모가 수백 개가 되자 목록이 너무 길어졌습니다. 키워드로 찾고, 10개씩 나눠 보는 기능이 필요합니다.

요구사항

  • GET /memos/search?q=키워드&page=1&size=10
  • 제목 또는 내용에 q 가 들어간 메모, 최신순
  • 응답: {"total", "page", "size", "items": [...]}
  • page ≥ 1, 1 ≤ size ≤ 50 (벗어나면 422)
힌트 보기
  • Query(1, ge=1), Query(10, ge=1, le=50) 로 범위 검증
  • OR 조건: Memo.title.contains(q) | Memo.content.contains(q)
  • 건너뛰기: .offset((page - 1) * size).limit(size)
  • total 은 offset/limit 을 걸기 전 개수

확인 방법

직접 확인
curl "http://127.0.0.1:8000/memos/search?q=회의&page=1&size=5"
curl "http://127.0.0.1:8000/memos/search?size=100"   # 422

심화3. 메모 일괄 등록 (전부 또는 전무)

상황

다른 시스템에서 옮겨 온 메모를 한 번에 등록해야 합니다. 중간에 하나라도 잘못되면 하나도 저장되면 안 됩니다.

요구사항

  • POST /memos/bulk, body 는 [{title, content}, ...] 배열
  • 1~20개만 허용, 아니면 400
  • 제목이 공백뿐인 항목이 하나라도 있으면 400 + 아무것도 저장하지 않음
  • 성공 시 생성된 메모 목록(id 포함) 반환
힌트 보기
  • 매개변수 타입을 list[MemoCreate] 로 쓰면 배열을 받습니다
  • 검사를 저장 전에 모두 끝내기
  • db.add_all(목록) → commit() 한 번 = 트랜잭션 하나
  • commit 실패 시 rollback()

확인 방법

직접 확인
curl -X POST http://127.0.0.1:8000/memos/bulk -H "Content-Type: application/json" \
     -d '[{"title":"a","content":"1"},{"title":"  ","content":"2"}]'
# 400 {"detail":"제목이 비어 있는 항목 번호: [1]"}  → GET /memos/ 개수 변화 없음

개념 1비밀번호는 해시로 저장

DB 가 유출돼도 비밀번호를 알 수 없도록 되돌릴 수 없는 해시만 저장합니다. bcrypt 는 매번 다른 salt 를 섞기 때문에 같은 비밀번호도 해시가 매번 다릅니다. 로그인할 때는 입력값을 같은 방식으로 다시 해시해 비교하는 verify() 를 씁니다.

해시 도우미
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def get_password_hash(password):
    return pwd_context.hash(password)

def verify_password(plain_password, hashed_password):
    return pwd_context.verify(plain_password, hashed_password)

def login(request: Request, signin_data: UserLogin, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.username == signin_data.username).first()
    if user and verify_password(signin_data.password, user.hashed_password):

개념 1서버: 실패도 정해진 모양으로

먼저 username 중복을 확인해 400 을 돌려주고, 그래도 저장 중 오류가 나면 db.rollback() 으로 세션을 되돌린 뒤 500 과 안내 문구를 돌려줍니다. HTTPException 은 항상 {"detail": "…"} 모양이라 화면에서 다루기 쉽습니다.

회원가입
existing_user = db.query(User).filter(User.username == signup_data.username).first()
if existing_user:
    raise HTTPException(status_code=400, detail="이미 동일 사용자 이름이 가입되어 있습니다.")
...
try:
    db.commit()
except Exception:
    db.rollback()
    raise HTTPException(status_code=500, detail="회원가입이 실패했습니다. 기입한 내용을 확인해보세요")
return {"message": "회원가입을 성공했습니다"}

개념 2화면: 상태 코드로 분기

fetch 는 네트워크가 끊길 때만 catch 로 갑니다. 401·400·500 은 정상 응답으로 취급되므로 response.status 를 직접 확인해야 합니다. 로그인에 성공하면 /memos/ 로 이동하고, 로그인하지 않은 채 /memos/ 에 오면 서버가 303 으로 홈에 돌려보냅니다.

로그인 응답 처리
.then(response => response.json().then(body => ({ status: response.status, body: body })))
.then(result => {
    if (result.status === 200) {
        alert(result.body.message);
        window.location.href = '/memos/';
    } else {
        throw new Error(result.body.detail || '로그인을 실패했습니다.');
    }
})
.catch(error => alert(error.message));
